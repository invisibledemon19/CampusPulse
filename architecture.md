# CampusPlus architecture

Read together with `design.md` and `techstack.md`. The backend agent follows sections 4 to 9 and 11 to 14 most closely. The frontend agent follows sections 3, 5, 10 and 13 most closely. Both read the whole file.

## 1. System overview

```
Browser (React 19 + Vite, static files on Vercel)
  |
  |-- Pages and components (frontend agent)
  |      uses only the functions in section 5
  |
  |-- Matching engine: src/utils/scoring.js (pure JavaScript, no network)
  |
  |-- Data layer: src/services/index.js (backend agent)
         |-- localAdapter: demo listings + localStorage for profile and saved items
         |-- firebaseAdapter (dynamic import, only in Firebase mode)
                |-- Cloud Firestore: opportunities, users, savedOpportunities, submissions
                |-- Firebase Authentication (Google, optional)
```

There is no custom server. The scoring runs in the browser. Security comes from Firestore Security Rules. Listings are added by the owner through a seed script or the Firebase Console, never by ordinary users.

## 4. Modes and storage

Mode is decided once at startup:

- Firebase mode: all four `VITE_FIREBASE_*` variables are non-empty and `VITE_FORCE_DEMO` is not `true`.
- Demo mode: everything else.

Behavior by mode:

| Item | Demo mode | Firebase mode, signed out | Firebase mode, signed in |
| --- | --- | --- | --- |
| Opportunities | `demoOpportunities.js` (labeled samples) | Firestore `opportunities` | Firestore `opportunities` |
| Profile | localStorage | localStorage | Firestore `users/{uid}` |
| Saved items | localStorage | localStorage | Firestore `savedOpportunities` |

Rules:

1. In Firebase mode the app never falls back to demo listings. If Firestore fails, show the error state. If the collection is empty, show the empty state. This prevents sample data from appearing as real data in production.
2. There is no automatic migration of local data into an account at sign in. State this on the Profile page (string in `design.md`). A one time "import local data" action is a later enhancement.
3. localStorage keys: `campusplus:profile:v1` and `campusplus:saved:v1`. Every read is wrapped in try/catch, parsed, validated with `validate.js`, and reset to empty on corrupt data. Every write is wrapped in try/catch and throws a `ServiceError` with code `storage-blocked` when the browser refuses (private mode, quota).
4. The Firebase SDK is imported only inside `firebaseAdapter.js` and `firebase.js`, and those two files are imported only through `import()` from `services/index.js`. In demo mode the Firebase code must never load. Verify with the bundle check and the network panel.
5. Timestamps from Firestore are converted to ISO strings inside the adapter. The UI never sees Firestore types.

## 5. Data layer contract (the interface between the two agents)

Everything below is exported from `src/services/index.js` and returns Promises unless stated. The frontend agent codes against these shapes and does not import from any other file in `services/`.

```js
getMode()                          // 'demo' | 'firebase'  (sync)
listOpportunities()                // Opportunity[]
getOpportunity(id)                 // Opportunity | null
getProfile()                       // Profile | null
saveProfile(profile)               // Profile  (throws ServiceError 'validation' with fieldErrors)
listSaved()                        // SavedOpportunity[]
saveOpportunity(opportunityId)     // SavedOpportunity  (idempotent, adds default next steps for the category)
unsaveOpportunity(opportunityId)   // void
updateSaved(opportunityId, patch)  // SavedOpportunity  (patch: applicationStatus, nextSteps, notes)
submitOpportunity(draft)           // void  (Firebase mode and signed in only)
subscribeAuth(callback)            // returns an unsubscribe function (sync). callback receives { uid, displayName } or null
signInWithGoogle()                 // void
signOut()                          // void
```

`ServiceError` has `code` (`validation`, `unavailable`, `permission`, `not-found`, `storage-blocked`, `not-signed-in`), `message` (plain English, safe to show), and optional `fieldErrors` (an object of field name to message). The UI shows `fieldErrors` under inputs and `message` in the error state. In demo mode `subscribeAuth` calls back once with `null` and never again, and `signInWithGoogle` is not offered in the UI.

Scoring contract (from `src/utils/scoring.js`):

```js
rankOpportunities(opportunities, profile, now = new Date())
// returns { ranked: ScoredOpportunity[], excluded: ScoredOpportunity[] }

/**
 * @typedef {Object} ScoredOpportunity
 * @property {Opportunity} opportunity
 * @property {number|null} score                  // integer 0 to 100, null when excluded or when profile is null
```

The frontend agent never recomputes scores or exclusions. Search, filters and sorting operate on the arrays returned by `rankOpportunities`. Search matches title, organizer, tags and city, case insensitive, using `normalizeTag` from `tags.js` for tag comparison. Filters combine with AND.

Default next steps by category (`src/data/defaultSteps.js`, task text is exactly this):

| Category | Steps |
| --- | --- |
| hackathon | Check eligibility and team size; Prepare a project idea; Confirm teammates; Confirm the venue or joining link; Register on the organizer's site |
| internship | Check eligibility; Update your resume; Collect portfolio or project links; Apply on the organizer's site; Note the interview date |
| workshop | Check prerequisites; Register on the organizer's site; Add the date to your calendar; Install the tools you need |
| event | Check eligibility; Register on the organizer's site; Confirm the venue; Add the date to your calendar |

## 6. Opportunity Fit Score specification

Implement exactly as written. Do not tune numbers without updating this section and the tests.

Weights (exported as `WEIGHTS`, and a test asserts they sum to 1):

```
S = 0.30*K + 0.20*E + 0.20*L + 0.15*B + 0.10*D + 0.05*F
score = Math.round(S)
```

Each component is an integer from 0 to 100. Missing data produces a neutral value and a warning, never a guess.

### 6.0 Order of evaluation per listing

1. Compute `daysLeft` (section 8).
2. Hard constraints, checked in this order. The first failure excludes the listing, sets `score` and `components` to `null`, and sets `excluded`:
   1. Closed: `status` is `closed` or `cancelled`, or `daysLeft < 0` when a deadline exists, or (no deadline and `startDate` exists and is before today). Messages: "Registration is closed.", "This event was cancelled.", "The event date has passed."
   2. Eligibility: `eligibilityLevels` is non-empty, does not contain `any`, the profile has an `educationLevel`, and the level is not in the list. Message: "Open to {levels joined with comma} students only. Your level is {level}."
   3. Budget: `registrationFee` is a number, the profile `maxRegistrationFee` is a number, and the fee is greater than the limit. Message: "Registration fee ₹{fee} is above your limit of ₹{limit}."
3. Otherwise compute components.

If `profile` is `null`: skip steps 2.2 and 2.3, set every `score` to `null`, `components` to `null`, and `reasons` to an empty array. Sort by `daysLeft` ascending (null last), then title. The UI then shows "Add your skills, city and fee limit to see fit scores."

### 6.1 Skills and interests (K)

1. `normalizeTag(s)`: trim, lowercase, collapse inner whitespace, remove characters other than letters, digits, spaces, `+`, `#` and `.`, then apply `aliases.js`. Starter aliases: `artificial intelligence` to `ai`, `machine learning` to `ml`, `js` to `javascript`, `node`, `node.js` and `nodejs` to `nodejs`, `reactjs` and `react.js` to `react`, `py` to `python`, and plural category words `hackathons`, `internships`, `workshops`, `events` to their singular forms.
2. `userTerms` = set of normalized skills and interests. `oppTerms` = set of normalized tags plus the normalized category.
3. If the listing has no tags, `K = 50` and warning "Skill tags not provided".
4. Else if `userTerms` is empty, `K = 50` and warning "Add skills and interests to improve matching".
5. Else `overlap = |userTerms intersect oppTerms|` and `K = min(100, round(100 * overlap / min(|oppTerms|, 3)))`.
6. Reason when overlap is above zero: "Matches your skills or interests: {up to 3 matched tags in the listing's original spelling}".

### 6.2 Eligibility (E)

- No `eligibilityLevels`: `E = 50`, warning "Eligibility not provided".
- Profile has no `educationLevel`: `E = 50`, warning "Add your education level to check eligibility".
- List contains `any` or the profile level: `E = 100`. Reason "Open to {level} students" (or "Open to all education levels" for `any`).
- Otherwise the listing was excluded in step 2.2.

### 6.3 Location (L)

- Format `online`: `L = 100`, reason "Held online, no travel needed".
- Format `offline` or `hybrid`:
  1. If both the listing and the profile have valid coordinates and the profile has `maxDistanceKm`: compute the haversine distance `d` (Earth radius 6371 km), round to a whole kilometer for display and keep `distanceKm`. If `d <= maxDistanceKm`, `L = round(100 - 30 * d / maxDistanceKm)` and reason "{d} km away, within your {max} km distance". Otherwise `L = 20` and warning "{d} km away, outside your {max} km distance".
  2. Otherwise compare cities after lowercasing and trimming. Listing city missing: `L = 50`, warning "Location not provided". Profile city missing: `L = 50`, warning "Add your city to check distance". Same city: `L = 100`, reason "In your city: {city}". Both cities in the same group in `regions.js`: `L = 70`, reason "In your region ({region name}), distance not calculated". Otherwise: `L = 30`, warning "Different city, distance not calculated".
  3. If the format is `hybrid`, `L = max(L, 80)`.
- `regions.js` starter data: one region named `NCR` containing `delhi`, `new delhi`, `noida`, `greater noida`, `ghaziabad`, `gurugram`, `gurgaon`, `faridabad`. The owner can add regions. Never invent coordinates for cities. Distances appear only when coordinates were supplied by the listing and by the user's explicit "Use my location" action.

### 6.4 Budget (B)

Registration fee only. `estimatedTravelCost` is displayed in the Cost section as a separate line labeled "Estimated travel (estimate)" and never changes the score.

- Fee is `null`: `B = 40`, warning "Registration fee not provided". Not excluded.
- Fee is `0`: `B = 100`, reason "Free to register".
- Profile limit is `null` (no limit) and fee above 0: `B = 70`, reason "Registration fee: ₹{fee}".
- Fee above 0 and not above the limit: `B = round(100 - 50 * fee / limit)`, reason "Fee ₹{fee} is within your limit of ₹{limit}".
- Fee above the limit: excluded in step 2.3.

### 6.5 Deadline relevance (D)

- No deadline: `D = 40`, warning "Deadline not provided".
- `daysLeft` 0 to 3: `D = 100`. 4 to 14: `D = 90`. 15 to 30: `D = 70`. Above 30: `D = 50`.
- Urgency object, shown separately from the score: `daysLeft` 0 gives level `today`, label "Closes today". 1 to 3 gives `urgent`, label "Closes in {n} day(s)". 4 to 14 gives `soon`. Above 14 gives `later`. No deadline gives `none`, label "Deadline not provided". Closed listings give `closed`, label "Closed on {date}" (or "Closed" when no date).

### 6.6 Format (F)

- Profile preference `any` or missing: `F = 100`, no reason.
- Same as listing format: `F = 100`, reason "Matches your preferred format: {format}".
- Listing is `hybrid` and the preference is `online` or `offline`: `F = 80`, reason "Hybrid, so you can attend either way".
- Otherwise `F = 30`.

### 6.7 Sorting

`ranked` is sorted by `score` descending, then `daysLeft` ascending with null last, then `title` using `localeCompare`. `excluded` is sorted by title. The UI offers other sorts (deadline soonest, event date soonest) by re-sorting the `ranked` array on the client.

### 6.8 Required test cases (`tests/scoring.test.js`)

Use a fixed `now` of `new Date(2026, 9, 24, 12, 0, 0)` (24 October 2026, local time).

Profile: undergraduate, Greater Noida, skills Python and JavaScript, interests AI and Hackathons, fee limit 0, preferred offline, no coordinates. Components K 100, E 100, L 70, B 100, D 90, F 100.
2. Paid listing with fee 500 and profile limit 0 is in `excluded` with code `budget` and has `score` null.
3. Deadline `2026-10-23` is excluded with code `closed`. Deadline `2026-10-24` is included with level `today`.
4. Profile level `undergraduate` against `eligibilityLevels: ['postgraduate']` is excluded with code `eligibility`.
5. Listing with no tags, null fee, null deadline, null city, empty eligibility, offline, profile preferring offline with limit 0 scores 50 with the matching warnings.
6. `Machine Learning` in the profile matches the tag `ML`.

8. Online listing for a user in another city gets `L = 100`.
9. Hybrid listing in a different city gets `L = 80`.

## 7. Data model (Firestore)

Four collections. The first three come from the blueprint. `submissions` is added so that community entries never go straight into public listings.

### 7.1 `opportunities` (public read, no client write)

| Field | Type | Rule |
| --- | --- | --- |
| `title` | string | 3 to 120 characters |
| `organizer` | string | 1 to 120 characters |
| `category` | string | `hackathon`, `internship`, `workshop`, `event` |
| `description` | string | up to 2000 characters |
| `tags` | string list | up to 15 items, each up to 40 characters |
| `registrationFee` | number or null | zero or greater |
| `estimatedTravelCost` | number or null | zero or greater |
| `format` | string | `online`, `offline`, `hybrid` |
| `city`, `venue` | string or null | up to 120 characters |
| `latitude`, `longitude` | number or null | both set or both null, ranges -90 to 90 and -180 to 180 |
| `startDate`, `deadline` | string or null | `YYYY-MM-DD` and a real calendar date |
| `eligibilityLevels` | string list | values from `diploma`, `undergraduate`, `postgraduate`, `doctoral`, `any` |
| `registrationUrl`, `sourceUrl` | string | empty string or a URL starting with `https://` |
| `lastCheckedAt` | timestamp or null | set only when a person or process really checked the source |
| `verificationStatus` | string | `unverified` or `verified` |
| `status` | string | `open`, `closed`, `cancelled`, `unknown` |
| `isSample` | boolean | true only for demo data |
| `createdAt` | timestamp | set by the seed script |

Integrity rules enforced by `validate.js` and the seed script: a listing marked `verified` must have a non-empty `sourceUrl` and a non-null `lastCheckedAt`. Sample listings are never `verified`. The UI shows "Verified by CampusPlus" only when `verificationStatus` is `verified` and `isSample` is false. Show "Last checked" only when `lastCheckedAt` exists.

### 7.2 `users` (document id is the Firebase UID, private)

Fields as in the `Profile` typedef. All of `displayName`, `educationLevel`, `location`, `maxDistanceKm`, `maxRegistrationFee`, `skills`, `interests`, `preferredFormat` are required (null allowed for the two numbers). `latitude` and `longitude` are optional.

### 7.3 `savedOpportunities` (private)

Document id is `{uid}_{opportunityId}`. This makes saving idempotent and prevents duplicates. Fields: `userId`, `opportunityId`, `savedAt` (server timestamp), `applicationStatus`, `nextSteps` (up to 20 items of `{id, task, completed}`, task up to 120 characters), `notes` (optional string, up to 1000 characters).

### 7.4 `submissions` (create only, no read)

Fields: `title`, `organizer`, `category`, `description`, `format`, `registrationUrl` (https only), `city` (optional), `deadline` (optional, `YYYY-MM-DD`), `submittedBy` (the UID), `submittedAt` (server timestamp). Submissions are reviewed by the owner in the Firebase Console. When approved, the owner copies the data into a proper `opportunities` record through the seed script, with a real `sourceUrl` and `lastCheckedAt`. No admin UI is built in the MVP.

### 7.5 Seed script (`scripts/seed.mjs`, backend agent)

- Reads `data/seed/opportunities.json`. The owner fills this file with real, manually checked listings. The agent must not fill it with invented events.
- Validates every record with the same functions as `src/utils/validate.js`. Any invalid record stops the run with a clear error and nothing is written.
- Rejects duplicates inside the file and against existing documents using normalized title plus organizer plus start date.
- Refuses records with `isSample: true` unless run with `--allow-sample`, and refuses `--allow-sample` when the project id is the production project.
- Uses `firebase-admin` with credentials from the `GOOGLE_APPLICATION_CREDENTIALS` environment variable, pointing to a key file stored outside the repository. Works against the emulator when `FIRESTORE_EMULATOR_HOST` is set.
- Uses `set` with merge on a stable id (slug of title, organizer and start date) so rerunning is safe.

## 8. Dates

All logic lives in `src/utils/dates.js`.

- Calendar dates (`startDate`, `deadline`) are strings `YYYY-MM-DD`. Never pass them to `new Date('YYYY-MM-DD')`, which is parsed as UTC and can shift the day in local time.
- `parseDateOnly(str)` returns `{ y, m, d }` or `null`. It checks the pattern and that the date exists (for example `2026-02-30` is invalid).
- `todayParts(now)` returns the local year, month and day of `now`. Local time is India time for the target users.
- `daysLeft(deadlineStr, now)` returns `(Date.UTC(dy, dm - 1, dd) - Date.UTC(ty, tm - 1, td)) / 86400000` as an integer, or `null` when the date is missing or invalid. A deadline is valid through the end of its day, so `0` means "closes today".
- `formatDate(str)` returns `15 Nov 2026` using a fixed month array (`Jan` to `Dec`), not `Intl`, so output does not vary between browsers. It returns "Not provided" for missing or invalid input.
- Demo data stores offsets and builds real date strings at load time (for example today plus 10 days), so the demo never goes stale. Include several listings with past deadlines to exercise the closed state.

## 9. Security: Firestore rules and authentication

### 9.1 `firestore.rules`

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    function signedIn() {
      return request.auth != null;
    }

    function isOwner(uid) {
      return signedIn() && request.auth.uid == uid;
    }

    function ownsDoc() {
      return signedIn() && resource.data.userId == request.auth.uid;
    }

    function validProfile(d) {
      return d.keys().hasAll(['displayName', 'educationLevel', 'location', 'maxDistanceKm', 'maxRegistrationFee', 'skills', 'interests', 'preferredFormat'])
        && d.keys().hasOnly(['displayName', 'educationLevel', 'location', 'maxDistanceKm', 'maxRegistrationFee', 'skills', 'interests', 'preferredFormat', 'latitude', 'longitude'])
        && d.displayName is string && d.displayName.size() >= 1 && d.displayName.size() <= 80
        && d.educationLevel in ['diploma', 'undergraduate', 'postgraduate', 'doctoral']
        && d.location is string && d.location.size() <= 80
        && (d.maxDistanceKm == null || (d.maxDistanceKm is number && d.maxDistanceKm >= 0 && d.maxDistanceKm <= 2000))
        && (d.maxRegistrationFee == null || (d.maxRegistrationFee is number && d.maxRegistrationFee >= 0))
        && d.skills is list && d.skills.size() <= 30
        && d.interests is list && d.interests.size() <= 30
        && d.preferredFormat in ['any', 'online', 'offline', 'hybrid']
        && (d.get('latitude', null) == null || (d.latitude is number && d.latitude >= -90 && d.latitude <= 90))
        && (d.get('longitude', null) == null || (d.longitude is number && d.longitude >= -180 && d.longitude <= 180));
    }

    function validSaved(d) {
      return d.keys().hasAll(['userId', 'opportunityId', 'savedAt', 'applicationStatus', 'nextSteps'])
        && d.keys().hasOnly(['userId', 'opportunityId', 'savedAt', 'applicationStatus', 'nextSteps', 'notes'])
        && d.opportunityId is string && d.opportunityId.size() > 0 && d.opportunityId.size() <= 128
        && d.applicationStatus in ['interested', 'preparing', 'applied', 'registered', 'completed']
        && d.nextSteps is list && d.nextSteps.size() <= 20
        && d.get('notes', '') is string && d.get('notes', '').size() <= 1000;
    }

    function validSubmission(d) {
      return d.keys().hasAll(['title', 'organizer', 'category', 'description', 'format', 'registrationUrl', 'submittedBy', 'submittedAt'])
        && d.keys().hasOnly(['title', 'organizer', 'category', 'description', 'format', 'registrationUrl', 'city', 'deadline', 'submittedBy', 'submittedAt'])
        && d.title is string && d.title.size() >= 3 && d.title.size() <= 120
        && d.organizer is string && d.organizer.size() >= 1 && d.organizer.size() <= 120
        && d.category in ['hackathon', 'internship', 'workshop', 'event']
        && d.description is string && d.description.size() <= 2000
        && d.format in ['online', 'offline', 'hybrid']
        && d.registrationUrl is string && d.registrationUrl.size() <= 500 && d.registrationUrl.matches('https://.+')
        && (d.get('city', null) == null || (d.city is string && d.city.size() <= 120))
        && (d.get('deadline', null) == null || (d.deadline is string && d.deadline.matches('[0-9]{4}-[0-9]{2}-[0-9]{2}')))
        && d.submittedBy == request.auth.uid
        && d.submittedAt == request.time;
    }

    match /opportunities/{id} {
      allow read: if true;
      allow write: if false;
    }

    match /users/{uid} {
      allow read: if isOwner(uid);
      allow create, update: if isOwner(uid) && validProfile(request.resource.data);
      allow delete: if isOwner(uid);
    }

    match /savedOpportunities/{docId} {
      allow read: if ownsDoc();
      allow create: if signedIn()
        && request.resource.data.userId == request.auth.uid
        && docId == request.auth.uid + '_' + request.resource.data.opportunityId
        && request.resource.data.savedAt == request.time
        && validSaved(request.resource.data);
      allow update: if ownsDoc()
        && validSaved(request.resource.data)
        && request.resource.data.userId == resource.data.userId
        && request.resource.data.opportunityId == resource.data.opportunityId
        && request.resource.data.savedAt == resource.data.savedAt;
      allow delete: if ownsDoc();
    }

    match /submissions/{id} {
      allow create: if signedIn() && validSubmission(request.resource.data);
      allow read, update, delete: if false;
    }

    match /{document=**} {
      allow read, write: if false;
    }
  }
}
```

The backend agent must test these rules in the emulator and fix any syntax or logic error found, instead of trusting this text. Required rules tests (`tests/rules/`):

1. Anyone can read `opportunities`. No one can write to it.
2. A signed out visitor cannot read or write `users` or `savedOpportunities`.
3. User A cannot read or write User B's profile or saved items.
4. User A can create `savedOpportunities/A_x` with `userId` A, and cannot create it with a mismatched id or a different `userId`.
5. A saved item update cannot change `opportunityId`, `userId` or `savedAt`.
6. A saved item with notes above 1000 characters, or an unknown status, is rejected.
7. An invalid profile (unknown education level, 31 skills, negative fee limit) is rejected.
8. A signed in user can create a valid submission. A submission with an `http://` URL or someone else's `submittedBy` is rejected. No one can read submissions.

The saved items query must filter by `where('userId', '==', uid)` so the read rule can pass. No composite index is needed because sorting happens in the browser. `firestore.indexes.json` can contain an empty `indexes` array.

### 10.2 `src/hooks/usePageMeta.js`

```js
import { useEffect } from 'react';

function setTag(tag, key, value, attr, content) {
  let el = document.head.querySelector(`${tag}[${key}="${value}"]`);
  if (!el) {
    el = document.createElement(tag);
    el.setAttribute(key, value);
    document.head.appendChild(el);
  }
  el.setAttribute(attr, content);
}

export function usePageMeta({ title, description, path = '/', noindex = false }) {
  useEffect(() => {
    const base = (import.meta.env.VITE_SITE_URL || window.location.origin).replace(/\/+$/, '');
    const url = base + path;
    document.title = title;
    setTag('meta', 'name', 'description', 'content', description);
    setTag('link', 'rel', 'canonical', 'href', url);
    setTag('meta', 'name', 'robots', 'content', noindex ? 'noindex,follow' : 'index,follow');
    setTag('meta', 'property', 'og:title', 'content', title);
    setTag('meta', 'property', 'og:description', 'content', description);
    setTag('meta', 'property', 'og:url', 'content', url);
  }, [title, description, path, noindex]);
}
```

Every page component calls this hook once with the values from `design.md` section 10 (titles of at most 60 characters, descriptions of at most 155). For `/opportunity/:id` build the title from the listing, cut the listing title with three periods if the full title tag would exceed 60 characters, and set `noindex` to `listing.isSample`. Each page renders exactly one `<h1>`.

### 10.3 `robots.txt` and `sitemap.xml`

Generated by `scripts/generate-seo.mjs` (see `techstack.md`). Production gets `Allow: /` and a `Sitemap:` line with the real domain. Preview deployments get `Disallow: /`. Private pages are not blocked in `robots.txt`, because a blocked page cannot show its `noindex` tag. They carry `noindex` through the hook instead.

### 10.4 Known limitation and later upgrade

Because the app renders in the browser, crawlers that do not run JavaScript see only the default head. Google runs JavaScript, so this is acceptable for the MVP. Later, prerender `/terms`, `/privacy`, `/nearby` and verified listing pages at build time, and add `Event` structured data for real verified events only. Never add structured data for sample listings.

## 11. Performance plan

- Route level code splitting with `React.lazy` for every page except Discover. Wrap routes in one `Suspense` with a static skeleton fallback.
- Firebase loaded through `import()` only in Firebase mode.
- No images in the interface, no web fonts from a CDN, only the font files listed in `design.md`.
- Search input is debounced by 200 ms. Filtering and scoring a few hundred listings is cheap, but score once per profile or data change using `useMemo`, not per keystroke.
- Fetch `opportunities` once per session with a limit of 500 documents. Add pagination only when real data exceeds that.
- Hashed assets in `/assets` are cached for one year (`vercel.json`).
- Build gate: `scripts/check-bundle.mjs` fails above 150 KB gzip of initial JavaScript.
- Lighthouse targets on the deployed home page, mobile profile: Performance 90 or higher, Accessibility 95 or higher, Best Practices 95 or higher, SEO 95 or higher. These are targets to measure, not guarantees.

## 12. Deployment and custom domain

### 12.1 Source control

1. `git init`, add the `.gitignore` from `techstack.md`, run `git status` and confirm no `.env`, key file, `dist` or `node_modules` is staged.
2. Create a GitHub repository, push `main`.

### 12.2 Firebase

1. In the Firebase Console create a project and add a Web app. Copy `apiKey`, `authDomain`, `projectId` and `appId` into local `.env` and later into Vercel.
2. Create the Firestore database in production mode. Choose the location `asia-south1` (Mumbai) for users in India. The location cannot be changed afterwards.
3. Authentication: enable the Google provider.
4. Deploy rules: `npx firebase login`, `npx firebase use --add` (select the project), then `npx firebase deploy --only firestore:rules,firestore:indexes`.
5. Seed real listings: set `GOOGLE_APPLICATION_CREDENTIALS` to a service account key stored outside the repository, then run `npm run seed`.

If Firebase takes too long, deploy demo mode first (leave the four Firebase variables empty) and connect Firebase afterwards.

### 12.3 Vercel

1. Import the GitHub repository. Framework preset Vite, build command `npm run build`, output directory `dist`.
2. Under Project Settings, set the Node.js version to 22 or newer.
3. Add environment variables for both Production and Preview: all `VITE_` values from `.env.example`. For the first deploy set `VITE_SITE_URL` to the `https://` URL Vercel assigns.
4. Deploy. Vite variables are baked in at build time, so after any change to an environment variable you must redeploy.

### 12.4 Custom domain

1. Buy the domain from any registrar. Check availability and renewal price first.
2. In Vercel open Project, Settings, Domains, and add the domain. Pick one primary host (either `example.com` or `www.example.com`). Vercel can redirect the other host to the primary. Do not serve the same site on both hosts without a redirect.
3. Add the DNS records that the Vercel dashboard shows for that domain at your registrar (normally an A record for the apex host and a CNAME for `www`). Use the exact values shown in your dashboard, because they can differ between projects. Alternatively, point the domain's nameservers to Vercel if you prefer.
4. Wait for DNS to propagate (minutes to a few hours). Vercel issues the HTTPS certificate automatically.
5. Set `VITE_SITE_URL` in Vercel to `https://` plus the primary host, with no trailing slash, then redeploy so canonical tags, Open Graph tags, `robots.txt` and the sitemap use the new domain.
6. In Firebase Console, Authentication, Settings, Authorized domains, add the primary host (and the other host if it serves any page).
7. Optional: verify the domain in Google Search Console and submit `/sitemap.xml`.

## 15. Corrections made to the blueprint

The blueprint is kept as the product source. These changes remove contradictions and gaps:

1. `status` in the sample document was `"sample"`, which mixes two ideas. Registration state is now `open`, `closed`, `cancelled` or `unknown`, and demo data is marked only by `isSample: true`.
2. A fourth collection, `submissions`, holds community suggestions so users can never write `verificationStatus` or publish a listing directly.
3. The sample listing placed Delhi against a user in Greater Noida. Matching now uses region groups (NCR) with a lower score than the same city, and distance only when real coordinates exist.
4. The blueprint dates were fixed. Demo dates are now relative to the current day so the demo does not expire.
5. Sample listing pages are `noindex` so demo data is never indexed by search engines.
6. `savedOpportunities` documents use `{uid}_{opportunityId}` as the id to prevent duplicates and to let rules check ownership.
7. The tagline "Stop searching. Start showing up." is removed from the hero in favor of concrete text.
8. Legal pages, custom 404, robots, sitemap, favicon set, per-page metadata and a bundle budget are added as required parts of the product.
